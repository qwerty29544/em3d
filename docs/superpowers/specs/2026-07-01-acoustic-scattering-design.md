## Выбранный подход

Выбран вариант 1: отдельный подпакет `em3d.acoustics`.

Обоснование:

- акустическое поле скалярное, а текущий электродинамический `Operator` является векторным и диадическим;
- акустическое ядро слабосингулярное и не требует `p.v.`-части и локального тензорного слагаемого;
- итерационные методы уже достаточно универсальны и могут быть переиспользованы через общий контракт `matvec/rmatvec/backend`;
- разделение снижает риск регрессий в электродинамической реализации.

Не выбран вариант обобщения существующего `src/em3d/operator.py` до scalar/vector/tensor, потому что он увеличивает риск поломки уже работающего электродинамического кода и усложняет тестирование.

## Математическая постановка

В рабочей области `Q` решается скалярное интегральное уравнение:

```text
u(x) - k0^2 ∫_Q G(x - y) chi(y) u(y) dy = u0(x),
G(r) = exp(i k0 |r|) / (4 pi |r|)
```

где:

- `u(x)` — полное акустическое поле внутри области;
- `u0(x)` — падающая плоская волна;
- `k0` — волновое число в фоновой среде;
- `G` — функция Грина свободного пространства;
- `chi(y)` — контраст среды.

### Соглашение по `eta`

Публичный API принимает поле `eta`.

Внутри метода оператор использует:

```python
chi = eta - 1
```

То есть:

- `eta = 1` означает фоновую среду без рассеяния;
- `eta != 1` задаёт акустическую неоднородность;
- в интегральном операторе всегда используется контраст `chi`;
- для экспериментов из статей значения `eta` задаются явно, а преобразование `eta - 1` выполняется централизованно в `AcousticProblem` или `AcousticOperator`.

Это соглашение устраняет неоднозначность между разными обозначениями wiki (`n`, `eta`, `n^2 - 1`, `eta - 1`) и делает физический фон явным.

## Публичный API

### `AcousticProblem`

```python
@dataclass
class AcousticProblem:
    grid: Grid
    k0: float
    eta: np.ndarray
    direction: tuple[float, float, float] = (0.0, 0.0, 1.0)
    amplitude: complex = 1.0

    @property
    def chi(self) -> np.ndarray:
        return self.eta - 1
```

Обязанности:

- проверять форму `eta == grid.N`;
- нормировать направление падающей волны;
- строить `u0 = amplitude * exp(i k0 direction · x)`;
- хранить `chi = eta - 1` как единственный контраст, используемый оператором.

### `AcousticOperator`

```python
class AcousticOperator:
    def __init__(self, problem: AcousticProblem, backend=None):
        ...

    def matvec(self, u):
        ...

    def rmatvec(self, v):
        ...
```

Оператор реализует:

```text
H u = u - B(chi * u)
```

где `B` — дискретная свёртка с коэффициентами `k0^2 G`.

`rmatvec` должен быть настоящим сопряжённым оператором:

```text
H* v = v - conj(chi) * B* v
```

Это важно для `TwoStep`, потому что двухшаговый метод использует `H* r`.

## FFT-оператор

Дискретизация:

```text
u_p - sum_q A_{p-q} chi_q u_q = u0_p
```

Коэффициент:

```text
A_{p-q} = k0^2 ∫_{cell_q} G(x_p - y) dy
```

Для первой реализации:

- off-diagonal cell: midpoint approximation `k0^2 * volume * G(x_p - x_q)`;
- diagonal cell: аналитическая аппроксимация через эквивалентный шар объёма ячейки.

Self-cell:

```text
a_cell = (3 * volume / (4 pi))^(1/3)
A_0 ≈ exp(i k0 a_cell) * (1 - i k0 a_cell) - 1
```

Эта формула соответствует интегралу:

```text
k0^2 ∫_0^a exp(i k0 r) r dr
```

FFT-ускорение:

- ядро встраивается в удвоенную область `2Nx x 2Ny x 2Nz`;
- поле `chi*u` дополняется нулями;
- выполняется scalar convolution;
- результат обрезается обратно до исходной области.

В отличие от электродинамики, здесь каждый блок матрицы скалярный, а не `3x3`.

## Материалы и геометрии

`materials.py` должен генерировать именно `eta`, а не `chi`.

Планируемые генераторы:

```python
eta_homogeneous(grid, eta_value)
eta_slab(grid, eta_inside, eta_outside=1.0, axis=0, width_fraction=0.5)
eta_sphere(grid, center, radius, eta_inside, eta_outside=1.0)
eta_ellipsoid(grid, center, radii, eta_inside, eta_outside=1.0)
eta_lattice(grid, inclusions, eta_background=1.0)
```

Для воспроизведения статей можно задавать `eta_background != 1`, если вся вычислительная область является неоднородной прозрачной структурой относительно внешнего фона. В операторе это автоматически превратится в `chi_background = eta_background - 1`.

## Дальняя зона

Рассеянное поле:

```text
u_s(x) = k0^2 ∫_Q G(x - y) chi(y) u(y) dy
```

Асимптотика при `|x| -> infinity`:

```text
u_s(x) ~ exp(i k0 r) / r * f(s)
f(s) = k0^2 / (4 pi) ∫_Q chi(y) u(y) exp(-i k0 s·y) dy
```

Публичные функции:

```python
farfield_amplitude(u, problem, directions)
scattering_pattern(u, problem, directions, normalize="max")
pattern_plane(u, problem, plane="xy", n_angles=360, normalize="max")
```

Для графиков использовать нормированные кривые, чтобы их можно было сравнивать с численными решениями без смешивания ошибок масштаба и формы.

Терминологически для акустики лучше использовать `scattering pattern` или `differential scattering cross section`; `RCS/ЭПР` допустимо только как аналогичная диагностическая величина, но не как электромагнитная ЭПР.

## Итерационные методы

Переиспользуются существующие:

- `em3d.solvers.sim.solve`;
- `em3d.solvers.bicgstab.solve`;
- `em3d.solvers.twostep.solve`.

Контракт для акустического оператора должен совпадать с электродинамическим:

- `operator.backend`;
- `operator.matvec(u)`;
- `operator.rmatvec(v)`;
- форма неизвестного поля: `(Nx, Ny, Nz)`;
- правая часть: скалярное поле той же формы.

Отдельно проверить `TwoStep`, потому что он чувствителен к корректности `rmatvec`.

## Оценка `gamma0`

Для малых сеток создаётся плотная scalar matrix:

```text
H = I - B diag(chi)
```

Далее используется уже реализованная геометрия спектра:

- собственные значения `H`;
- выпуклая оболочка методом Эндрю;
- окружность, видимая из начала координат под минимальным углом;
- параметр `gamma0`.

Новая акустическая функция должна принимать крупную задачу и строить coarse problem:

```python
estimate_gamma0_from_problem(problem, coarse_N=(6, 6, 6), k=10)
```

Входной `eta` на грубой сетке строится повторной генерацией материала или downsampling-ом, но в обоих случаях в операторе применяется `eta - 1`.

## Риски

### Неоднозначность обозначений `eta`

Риск: в статьях и wiki встречаются разные соглашения для рефракционного параметра и контраста.

Решение: публично принимаем `eta`, внутри всегда используем `chi = eta - 1`. Это фиксируется в API, тестах и документации.

### Некорректный `rmatvec`

Риск: `TwoStep` может демонстрировать неправильную сходимость, если сопряжённый оператор реализован как простой повтор `matvec`.

Решение: обязательный adjoint-тест на случайных комплексных полях.

### Self-cell аппроксимация

Риск: diagonal коэффициент влияет на спектр и сходимость, особенно на грубых сетках.

Решение: отдельный тест self-cell и сравнение dense/FFT; в документации явно указать используемую аппроксимацию.

### Смешивание acoustic pattern и ЭПР

Риск: некорректная физическая терминология при переносе электродинамического языка.

Решение: в акустическом модуле использовать `scattering_pattern`; `RCS` оставить только как аналогичный нормированный диагностический график в экспериментах, если это явно подписано.
