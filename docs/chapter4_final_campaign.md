# Окончательный вычислительный стенд главы 4

## Назначение

Стенд формирует единый воспроизводимый массив результатов для разделов 4.2–4.7 диссертации. Он не предполагает, что все методы обязаны сходиться во всех режимах. Отсутствие спектрального параметра, потеря устойчивости, достижение максимального бюджета действий оператора и CUDA OOM регистрируются как самостоятельные результаты.

## Этапы кампании

| Этап | Содержание | Основной результат |
|---|---|---|
| `smoke` | сокращённые спектральные и all-solvers тесты | проверка установки, CUDA, Ми, FFT-оператора, решателей и экспорта |
| `spectral` | S4.2 и E0–E6 | фиксированная спектральная серия двух анизотропных сред; перенос параметра, Arnoldi, геометрическое разрешение, усреднение, ансамбль, фазовая карта |
| `main64` | полная Ми-серия и стационарные задачи | N=24,32,48,64; SIM/BiCGStab/TwoStep; поля и ЭПР |
| `audit` | строгий допуск | повтор выбранных режимов при истинной невязке 1e-8 |
| `control96` | крупносеточный контроль | пять Mie-режимов и три стационарные задачи на N=96 |
| `control128` | предельный контроль T4 | три обязательные Mie-задачи, две стационарные; один опциональный режим |
| `merge` | итоговая сборка | сводные таблицы главы, выбранные рисунки, компактный core-архив |

Рекомендуемая последовательность:

```text
smoke -> spectral -> main64 -> audit -> control96 -> control128 -> merge
```


## Фиксированная спектральная серия раздела 4.2

До межсеточных исследований выполняется самостоятельное сканирование на одной грубой дискретизации:

```text
real anisotropy  = diag(2, 1, 3),       k0 = 0,1,...,10
lossy anisotropy = diag(2+i, 1+i, 3+i), k0 = 0,2,...,10
N = 6, N_Q = 216
```

Выбор `N=6` сделан явно: в прежней редакции текста одновременно указаны `N=8` и `N_Q=216`; только `6^3=216`. Вещественный тензор принят равным `diag(2,1,3)`, чтобы он отличался от комплексного `diag(2+i,1+i,3+i)` только потерями. Это устраняет вторую несогласованность прежней редакции, где в вещественной формуле стояла вырожденная третья компонента `0`, хотя последующее описание предполагало существование допустимой окружности. Для каждой точки сохраняются полный спектр, выпуклая оболочка, окружность, параметры `mu`, `R`, `q`, история SIM и статус существования параметра. Эта серия отвечает только на вопрос об изменении спектра при фиксированной дискретизации; межсеточный перенос исследуется отдельно в E0–E6.

## Матрица основной серии Ми

```text
eps_r = 1.5, 2.25, 4.0
k0 a  = 0.5, 1, 2, 4, 6
N     = 24, 32, 48, 64
solver = SIM, BiCGStab, TwoStep
```

Всего: 60 дискретных задач и 180 запусков решателей. Каждый метод квалифицируется только по независимо пересчитанной истинной относительной невязке.

## Аудит допуска

При `audit` повторяются режимы:

```text
(eps_r, k0a) = (1.5,1), (1.5,4), (2.25,2), (4,1), (4,4)
N = 48, 64
true rtol = 1e-8
```

Это отделяет влияние алгебраического допуска от пространственной ошибки.

## Контрольные сетки

### N=96

```text
(1.5,0.5), (2.25,2), (2.25,6), (4,4), (4,6)
```

### N=128

Обязательные:

```text
(1.5,0.5), (2.25,6), (4,4)
```

Опциональная:

```text
(4,6)
```

Каждое крупное задание запускается отдельным процессом после memory-probe. Случай OOM не уничтожает результаты остальных заданий.

## Два stress-case для спектральной настройки

Одна физическая задача с локальным включением выполняется в двух вариантах:

```text
local_inclusion_stress_single_N5_N64
local_inclusion_stress_ensemble_5_6_7_N64
```

Первый использует параметр только по спектру N_H=5 и предназначен для воспроизведения неустойчивого переноса. Второй использует ансамбль 5+6+7 и показывает эффект робастной спектральной локализации. Их нельзя объединять под одним названием.

## Компактное архивирование

Полные деревья рисунков и массивы полевых срезов не включаются в итоговый `*-core.zip`. Core-архив содержит:

- манифесты и конфигурации;
- таблицы;
- структурированные логи;
- истории невязок;
- численные кривые ЭПР;
- выбранные публикационные рисунки.

Полные архивы полей и рисунков формируются отдельно в каталоге `archives/`.

## Запуск

Основной файл:

```text
notebooks/em-chapter4-final-kaggle.ipynb
```

В пользовательской ячейке изменяется только:

```python
RUN_STAGE = "main64"
BATCH_INDEX = 0
BATCH_COUNT = 1
INCLUDE_OPTIONAL = False
```

Для итогового объединения результаты предыдущих сеансов подключаются как Kaggle datasets и передаются через `EM3D_MERGE_INPUTS`; при отсутствии переменной блокнот пытается обнаружить завершённые манифесты в `/kaggle/input`.
