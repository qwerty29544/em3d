# LLM Wiki Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scaffold a persistent Obsidian-based research wiki for a dissertation on efficient Fourier methods for VIE in acoustics and electrodynamics, with full LLM workflow protocols in Russian.

**Architecture:** A `wiki/` directory serves as the Obsidian vault and git repo root. Raw sources live in `raw/` (immutable). Five wiki zones (`literature/`, `concepts/`, `research/`, `code/`, `writing/`) are owned by the LLM. A `CLAUDE.md` schema file governs all LLM behavior in every future session.

**Tech Stack:** Markdown, YAML frontmatter, Obsidian, Git — no build tools or dependencies.

## СТРУКТУРА ВИКИ

Корень хранилища Obsidian: `wiki/`

### Зоны
| Зона | Путь | Описание |
|------|------|----------|
| Литература | `literature/` | Резюме статей и источников — создаётся LLM |
| Концепции | `concepts/` | Математические сущности, методы, теоремы |
| Исследование | `research/` | Тезисы автора, доказательства, гипотезы, открытые вопросы |
| Код | `code/` | Заметки о решателях, результаты экспериментов |
| Написание | `writing/` | Черновики разделов диссертации |

### Именование файлов
Всегда: `зона/kebab-case-title.md` (только латиница и дефисы в имени файла).
Заголовки страниц в frontmatter и заголовках секций — на русском.

Примеры:
- `concepts/volume-integral-equation.md`
- `literature/vainikko-2000.md`
- `code/gmres-fft-solver.md`

### Frontmatter (обязателен для всех страниц)

```yaml
---
title: <Заголовок на русском>
zone: literature | concepts | research | code | writing
tags: [тег1, тег2]
sources: [literature/ключ-цитирования]   # только если применимо
status: draft | stable | needs-review
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

### Специальные файлы
- `index.md` — каталог всех страниц вики; LLM обновляет при каждой операции
- `log.md` — хронологическая история операций; только добавление записей
- `raw/` — исходные документы; LLM читает, но **никогда не изменяет**
- `research/thesis.md` — текущая формулировка диссертационного тезиса

## ПРОТОКОЛЫ

### INGEST (приём источника)

**Триггер:** "ingest `raw/papers/автор-год.pdf`" (или docx, pptx, web, notes)

**Шаги:**
1. Извлечь текст/содержимое:
   - PDF → использовать скилл `anthropic-skills:pdf`
   - DOCX → использовать скилл `anthropic-skills:docx`
   - PPTX → использовать скилл `anthropic-skills:pptx`
   - Markdown / текст → прочитать напрямую
2. Обсудить с автором ключевые выводы
3. Создать страницу в `literature/` по шаблону (раздел ШАБЛОНЫ ниже)
4. Создать или обновить соответствующие страницы в `concepts/`
5. Обновить `research/thesis.md`, если источник влияет на тезис
6. **Явно указать** противоречия с существующим содержимым вики
7. Добавить запись в `log.md` (формат — раздел ФОРМАТЫ ниже)
8. Обновить `index.md`

Один источник как правило затрагивает 5–15 страниц вики.

---

### QUERY (запрос к вики)

**Триггер:** любой вопрос о предметной области

**Шаги:**
1. Прочитать `index.md` для поиска релевантных страниц
2. Прочитать найденные страницы
3. Синтезировать ответ на русском языке с цитатами в формате `[[страница]]`
4. Предложить сохранить ответ как новую страницу `research/` или `writing/`, если он ценен
5. Добавить запись в `log.md`

---

### WRITING (написание текста)

**Триггер:** "напиши черновик раздела о..."

**Шаги:**
1. Найти релевантные страницы `literature/` и `concepts/` через `index.md`
2. Написать академический текст на русском языке
3. Сохранить в `writing/kebab-case-title.md`
4. Добавить ссылку на новую страницу в `index.md`
5. Добавить запись в `log.md`

---

### CODE (поддержка кода)

**Триггер:** автор описывает решатель, алгоритм или эксперимент

**Шаги:**
1. Создать страницу `code/` по шаблону (раздел ШАБЛОНЫ ниже)
2. Добавить ссылки на релевантные страницы `concepts/`
3. Обновить `index.md`
4. Предложить анализ сложности или сравнение с родственными методами
5. Добавить запись в `log.md`

---

### LINT (проверка вики)

**Триггер:** "проверь вики"

**Проверить:**
- Страницы без входящих ссылок (сироты)
- Устаревшие утверждения, опровергнутые более новыми источниками
- Концепции, упомянутые в `literature/`, но не имеющие страницы в `concepts/`
- Отсутствующие перекрёстные ссылки между связанными страницами
- Пробелы в данных — предложить новые источники для поиска
- Внутренние противоречия между страницами

**Отчёт:** на русском языке, в виде приоритизированного списка действий.
Добавить запись в `log.md`.
